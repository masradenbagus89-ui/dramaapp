## §4.7 Alur Berpemandu Bertahap (Progressive Guided Flow) — DETAIL on-demand

> Versi 1 · 2026-07-12 · Rumah detail untuk `CLAUDE_universal_v1.md` §4.7. Mandat ringkas (pecah bernomor · INFO→POPUP · anti-buntu · tutup "✅ SELESAI + rekap" · status jujur selesai-sebagian) TETAP di berkas aturan; 7 aturan lengkap + larangan + analogi pindah ke sini. Dibaca saat mulai kerja multi-langkah ke staff non-programmer (audit, refactor, setup, pecah-repo, migrasi, bulk docs).

Berlaku di SEMUA project lintasAI untuk tiap kerja >1 langkah.

### 7 aturan inti
1. **Pecah jadi langkah bernomor + peta di awal.** "Ini N langkah, mulai dari 1."
2. **Tiap langkah: INFO dulu → baru POPUP.** Tampilkan hasil ringkas (jangan tumpuk sekaligus), lalu popup klik untuk pilih langkah berikutnya.
3. **Lanjut otomatis — DILARANG buntu.** Setelah user pilih, langsung kerjakan + lanjut popup berikutnya. Jangan berhenti dengan cara yang memaksa user re-prompt. Selalu ada jalan lewat popup sampai user pilih "stop".
4. **Tunjukkan posisi + tutup tiap langkah.** "Langkah 2 dari 5" + "✅ Selesai X. Berikutnya Y".
5. **Anti-capek (decision fatigue).** Item banyak (mis. 55 temuan) → JANGAN 1 popup/item. Kelompokkan + opsi borong: "kerjakan semua / pilih satu-satu / lewati".
6. **Langkah TERAKHIR WAJIB: "✅ SELESAI" + REKAP RINCI** — apa yang dikerjakan tiap langkah, hasil, **apa yang diubah vs TIDAK diubah**, langkah berikutnya. Lalu popup penutup.
7. **Selesai-sebagian = status JUJUR.** Lacak tiap temuan di 3 keranjang: **✅ Selesai** · **☑️ Diterima-dengan-alasan** · **⏳ Tertunda**. Masih ada ⏳ → lapor "Selesai sebagian", bukan "✅ SELESAI" penuh. 🏢 kurir jujur: "3 dari 5 paket terkirim, 2 besok".

### Larangan
Dump laporan raksasa lalu diam · berhenti di tengah tanpa popup lanjut · selesai tanpa "✅ SELESAI + rekap" · cap "✅ SELESAI" penuh padahal masih ada ⏳.
