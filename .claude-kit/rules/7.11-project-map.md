# §7.11 Peta Aktivitas Project → draf roadmap (human-gated)

> Rujukan on-demand. Dipakai saat staff minta **"bikin roadmap / peta jalan / rencana / denah project / apa progres belakangan ini"**.

## Inti (1 kalimat)
Robot `npx lintasai project-map` memberi **fakta** dari riwayat commit; AI memakainya (bersama peta yang sudah ada) untuk menyusun **draf** roadmap yang **WAJIB disetujui manusia** sebelum ditulis ke mana pun. Robot TIDAK pernah menulis roadmap sendiri.

🏢 Analogi: robot = **buku tamu proyek** (mencatat siapa menyentuh ruangan mana, kapan). Buku tamu bukan denah gedung dan bukan rencana renovasi — tapi bahan berguna saat kamu menyusun rencana.

## Kenapa aman (patuh ADR-001 & ADR-009)
- **Fakta, bukan tebakan.** Riwayat commit = kebenaran yang tercatat; tak ada mode-gagal "kelewat 1 pemanggil" seperti graf-pemanggil yang ditolak ADR-001.
- **On-demand.** Jalan hanya saat diminta (nol beban token baseline) — bukan robot yang jalan tiap sesi.
- **Tak klaim lengkap.** Header output jujur: "aktivitas git di JENDELA INI, bukan peta lengkap / bukan roadmap". Modul "tak tersentuh" = fakta ("tak ada commit di jendela ini"), BUKAN vonis "mati/selesai".
- **Memberi umpan ke peta tunggal, bukan peta tandingan.** Nama modul diambil dari `project.lintas.jsonc` — memperkuat SSOT (§7.9/§7.4), bukan bikin indeks basi baru.

## Alur 5 langkah (WAJIB urut; jangan loncat ke "menulis" tanpa gerbang)

1. **Ambil FAKTA git.** `npx lintasai project-map --json` (atau `--since <tag>` untuk sejak rilis terakhir, `--limit <n>` untuk N commit terakhir). Hasil = commit per-modul, per-tipe (feat/fix/refactor/...), jendela waktu/tag, modul tak-tersentuh, folder aktif tanpa modul di kartu.
2. **Baca peta tunggal yang sudah ada** (jangan ulang meraba repo): kartu `project.lintas.jsonc` (`modules[]`) + `docs/architecture.md` (tabel "Peta Modul → Lokasi" + "Riwayat Perubahan").
3. **Baca NIAT (apa yang sedang/akan dikerjakan):** dokumen rencana di `docs/plans/*` + bagian `## [Belum Dirilis]` di `CHANGELOG.md`. Ini sumber "masa depan" — sebab **roadmap = rencana, tak bisa diturunkan dari git (git = masa lalu)**.
4. **Susun DRAF** roadmap/peta, semua berlabel **"observasi dari fakta git"** (bukan status pasti):
   - **Modul panas** = aktivitas commit tinggi belakangan (dari langkah 1).
   - **Modul deklarasi yang sepi** = ada di kartu tapi 0 commit di jendela (fakta; tanya apakah memang ditunda/selesai — jangan vonis sendiri).
   - **Sinyal campuran tipe** = semua `fix` → fase menstabilkan; lonjakan `feat` → fase ekspansi.
   - **Folder aktif tanpa modul di kartu** → sarankan tambah ke `project.lintas.jsonc` `modules[]`.
5. **GERBANG MANUSIA (tak bisa dilewati).** Sajikan draf sebagai usulan lewat popup `AskUserQuestion` (§14.1, `rules/14.1-popup-ui.md`) — staff menyetujui/menyunting DULU. Baru setelah "ya" AI menulis ke `docs/plans/<nama>.md` atau memperbarui `docs/architecture.md`. Sajian bertahap (§4.7): info → popup → lanjut, tutup "✅ SELESAI + rekap".

## Larangan
- ❌ Menyebut hasil robot sebagai "peta lengkap project" atau "roadmap pasti" — itu fakta aktivitas, bukan rencana final.
- ❌ Memvonis modul "mati/ditinggalkan" hanya karena 0 commit di jendela (§8.2 Aturan 3b: jangan asal flag) — laporkan sebagai fakta + tanya.
- ❌ Menulis roadmap ke berkas TANPA persetujuan manusia (langkah 5). Robot tak punya jalur tulis; AI pun menunggu "ya".
- ❌ Menjalankan robot sebagai daemon / tiap sesi — ini on-demand.

## Bahasa (§2.1)
Saat melaporkan ke staff: pakai bahasa awam. "commit" → "perubahan yang disimpan"; "modul" → "bagian project"; "jendela sejak tag" → "sejak rilis terakhir". Jelaskan tiap jargon di kemunculan pertama.

## Rujukan
- Robot + batas jujur: `docs/project-map.md` (pendamping `engine/project-map.mjs`).
- Keputusan + rekonsiliasi dengan ADR-001: (ADR-011) — catatan internal repo-kit, tidak ikut terkirim ke project client.
- Aturan sajian bertahap: §4.7. Popup: §14.1. Peta tunggal: §7.4/§7.9.
