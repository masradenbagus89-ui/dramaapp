## 4.19 Format Rencana Plan-Mode — Pindai Cepat + tangga belajar 2-versi + klaim berbukti (rujukan on-demand)

> Mandat ringkas selalu-aktif = `CLAUDE_universal_v1.md` §4.19 — CUKUP untuk rencana rutin/sepele. Berkas ini dibaca HANYA saat: Plan mode harness aktif, rencana besar/multi-sesi, atau ragu format — BUKAN tiap rencana kecil.
> **Filosofi (§4.17 "Perkuat, Jangan Kurung"):** otak Claude = sopir yang menyusun rencana/analisa/saran TERBAIK dengan penalaran bebasnya. §4.19 hanya MENGUATKAN (akurasi berbukti + pagar titik-risiko + bahasa awam), TIDAK mengekang. Kalau aturan terasa mengekang rencana yang lebih baik, itu SALAH.
> **Berlaku semua mode:** aturan akurasi (Matriks/Pernyataan Cakupan/reverse-ref/migration-timeline) di-akar-kan ke §7.3a/§8.2/§6.3 → berlaku di mode APA PUN. Yang KHAS Plan mode cuma FORMAT-sajian + hook pengingat.

### Alur Pindai Cepat (bercabang di langkah-0)

Tiap langkah = 1 baris + nomor seksi sumber (TANPA menyalin isi). Robot pra-pindai opsional: `npx lintasai plan-scout "<kata kunci>"` di project besar → ringkasan "mulai lihat di sini" sebelum baca apa pun.

**(a) Proyek BERJALAN (ada kode):**
1. **Peta dulu** → §7.9 (kartu `project.lintas.jsonc`) / §7.3 (`docs/architecture.md`). Kartu **KOSONG** (`purpose:'pending'`/`modules:[]`) → "baca 1 peta" TAK tuntas: TAWARKAN isi dulu (§7.9, human-gated, `npx lintasai project-map`); tanpa kartu → `architecture.md` → Grep. **Kartu BASI** (path tak cocok kenyataan) → jatuh ke Grep, JANGAN percaya kartu.
2. **Sasaran + ambang** → Grep kata-kunci → ambang berhenti §6.3 Sample-and-Expand (3 berkas berturut tanpa temuan baru / ±15 berkas per area / batas-luar DB-HTTP). **Ambang CONTENT-based**, bukan hitung-berkas: berhenti/klaim HANYA setelah berkas-OTORITATIF terbaca (lihat Matriks + migrasi-berurut).
3. **Bukti** → §8.2/§4.2-0 (pisah ✅ vs ❓). **Task 1-berkas kosmetik/teks murni** (uji-balik: tak ada indireksi i18n/CMS/DB) → LEWATI baca-peta, langsung Grep (jalur-remeh super-ringan).

**(b) Proyek BARU / "bikin website-aplikasi dari nol":** JANGAN memindai (tak ada yang dipindai) → langsung §4.2c (gali kebutuhan + Peta Aplikasi) + tunjuk resep kapabilitas `workflows/cap/` (login/pembayaran/upload/realtime/dll.). Kedua cabang keluar dengan format sajian sama.

**Pas-ukuran fan-out:** default Pindai Cepat = **NOL fan-out agen** KECUALI user minta "menyeluruh/audit/deep" ATAU rencana menyentuh titik-risiko §4.17 (auth/bayar/data-pribadi/skema-DB). Sajikan rencana BEGITU klaim penyetir-keputusan ✅ DAN ambang tercapai — dilarang menunda demi "baca lebih banyak biar yakin".

### MATRIKS Intent → Kedalaman → Wajib-✅ (JANTUNG; mengganti ambang "3-jenuh" flat)

Baris = **KELUARGA-intent** (otak Claude memetakan prompt natural → keluarga; bukan daftar-tutup). Debug/saran/rekomendasi = keluarga BACA/SARAN; upgrade/tambah/edit = UBAH; audit-menyeluruh/deploy/online = 8-DIMENSI.

| Intent | Kedalaman | Berkas-otoritatif WAJIB | Bukti wajib sebelum klaim |
|---|---|---|---|
| **BACA/SARAN** (kondisi/"jelasin"/"apa perlu diperbaiki"/audit/debug) | Pindai Cepat + berkas-niat + berkas-otoritatif per objek; TAK berhenti di 3-jenuh bila sentuh titik-risiko | robots.ts/next.config · supabase.ts(db.schema) · config.toml(verify_jwt) · migrasi ber-nomor TERTINGGI per objek RLS/GRANT | **Pernyataan Cakupan** (✅diperiksa vs ❓BELUM); negasi dilarang dari 1 grep |
| **UBAH** (upgrade/tambah/edit) | Pindai Cepat + kode asli target + pemanggil langsung (§7.3a) + peta rute nyata | tabel rute (createBrowserRouter/KEEP_ALIVE) · helper eksisting · konvensi-samping (logActivity/audit) · supabase.ts | Pola-Ditiru nyata `berkas:baris` + validasi "halaman=berkas" ke rute |
| **HAPUS** (buang halaman/fitur) | Sapuan-Referensi-Terbalik PENUH | glob SEMUA router · tiap named+default export · string path · simbol DB lintas src+app+supabase+types+.github | Kelengkapan-pemakai; ADA hasil → batalkan klaim yatim |
| **8-DIMENSI** (audit menyeluruh/deploy/online/CI) | Uji-keberadaan tabel-kandidat DIPERLUAS | supabase/functions+config.toml · .github/workflows · sinyal package.json | Negasi dilarang dari 1-file-absen; gap §11 ⚠️ otomatis |

**Aturan migrasi-berurut (P2):** klaim menyentuh RLS/GRANT/policy sebuah objek → `grep -l <objek> migrations/*` (atau `plan-scout --migration-timeline <objek>`) → baca migrasi ber-nomor **TERTINGGI** per objek + cek migrasi "lockdown/revoke/fix" terakhir. State EFEKTIF = migrasi tertinggi, BUKAN grep pertama. **Di titik-risiko, ✅ SAH hanya bila berkas-otoritatif (migrasi terakhir/config nyata) terbaca; belum → WAJIB ❓, DILARANG memaksa ✅** (memaksa ✅ di atas subset basi = rasa-yakin palsu).

### Tabel kandidat-periksa 8-dimensi (uji keberadaan DULU via robot murah, baru baca; jatuh ke Grep bila tak ada; periksa HANYA yang disentuh rencana)

JANGAN berasumsi dari tabel — ini NAVIGASI, bukan bukti. TANPA nomor baris (rujukan seksi saja; robot hanya jaga path putus, bukan baris).

| Dimensi | Uji-keberadaan | Catatan |
|---|---|---|
| Next.js | `app|pages/`, `next.config.*` — **pisahkan framework-terpasang (biner) vs pola-routing (baca kode)** | grep `ssr:false`+`createBrowserRouter`+`[[...slug]]` → **SPA-in-Next** → matikan saran metadata-per-halaman, alihkan ke konvensi react-router nyata |
| Supabase | `supabase/migrations/`, SQL RLS, `.env.example` | fitur ber-tabel → baca `supabase.ts`(db.schema)+1 migrasi contoh DULU |
| deploy | `vercel.json|render.yaml|railway.json` (kanonik) + sinyal-turunan `next build`/`Dockerfile`/`fly.toml` | `railway.toml` = varian Railway opsional; nihil semua → "belum terdeteksi" (BUKAN "tidak-deploy") |
| API / Edge Functions | `supabase/functions/` (Deno: `Deno.env`/`serve(`) · `app/**/route.ts`/`pages/api/` (Next) · `middleware.ts` | area API + titik-risiko → baca `supabase/config.toml` (verify_jwt; mis. partner-api verify_jwt=false sengaja) sebelum klaim proteksi |
| SEO | grep `generateMetadata|sitemap.ts|robots.ts` | **berkas-niat**: baca `app/robots.ts`+`next.config` DULU — noindex global → "SEO tak relevan (tool internal by design)", BUKAN gap |
| DevOps / CI | `.github/workflows/*.yml` (+`.gitlab-ci.yml`, `Dockerfile`, `*.tf`) | sasaran Grep saat prompt sentuh CI/backup/pipeline |
| Observability | `@sentry`/`pino`/`winston` di package.json · healthcheck route · `npx lintasai env-keys` | nihil + prompt "mau online" → gap §11 ⚠️ otomatis di konfirmasi-lingkup |
| BE/FE + Python | `app/api/**|pages/api/**` vs komponen + `modules[]` kartu · Python `pyproject.toml|requirements.txt|manage.py` | tim owner memakai Python (auto-terdeteksi kit) |

Kedalaman MUTU tiap dimensi → rujuk stack-pack §4.14 (JANGAN salin). **Baris konvensi-grounding (saat rencana akan MENULIS kode):** tangkap contoh-teratas per konsern (Naming/Error-handling/Data-access/Tests) + `berkas:baris`; tak ada contoh di repo → NYATAKAN eksplisit, JANGAN mengarang pola.

### Stack-DoD otomatis — "Definisi Selesai per-Stack" (masuk konfirmasi-lingkup saat MEMBANGUN fitur)

RUJUK aturan tersebar (jangan salin), centang yang relevan dengan intent+stack; tak relevan → "tak relevan (alasan)":
- 🔧 Backend/API · 🎨 Frontend **4 state UI** loading/empty/error/success (§5)
- 🗄️ Database RLS aktif + migrasi reversible+rollback (§9 expand-then-contract)
- 🖌️ Webdesign + 👥 UI/UX/aksesibilitas ("keren tapi benar"): a11y WCAG (label · fokus-keyboard terlihat · tap-target ~44px · kontras ≥4.5:1) · design token (bukan hardcode warna/spacing) · mobile-first responsive (~360px) · heading semantik · microcopy aktif ≤8 kata (§10)
- ☁️ DevOps env keys (`npx lintasai env-keys`) + observability §11
- 🔒 Security rate-limit/otorisasi titik-sensitif (§8)
- 📈 SEO metadata (§10) — TAPI cek robots.ts dulu (berkas-niat)

### Gerbang Bukti-Jalan (saat fitur DIEKSEKUSI, sebelum "selesai" — bukan cuma tes unit)

Bukti RUNTIME nyata: `npm run build` LULUS (tangkap error tipe/import yang dev-server sembunyikan) · RLS TERBUKTI menolak (query sbg role rendah / `execute_sql` read-only di staging — JANGAN ubah data prod, §8.2 Aturan 3) · env keys target ada · smoke 3-5 alur kritikal §11. Pakai skill `verify`/`run` bila tersedia. Efek di runtime client = ⏳ sampai owner konfirmasi (§4.6).

### Sub-protokol HAPUS (dipicu HANYA intent=HAPUS) — Sapuan-Referensi-Terbalik

1. Enumerasi DULU SEMUA berkas router (glob `createBrowserRouter|createRoutesFromElements|RouterProvider`; atau `plan-scout --reverse-ref <Nama>`) — DILARANG klaim "tak dipakai" bila router-disapu < router-ada.
2. Grep SIMBOL: default export + SETIAP named export (mis. `DomainOverviewContent`, bukan cuma `DomainOverviewPage`) + string path route (`/ip-bypass`) + dynamic import path (`@/screens/...`) lintas src/**+app/**+supabase/**.
3. ADA hasil → BATALKAN klaim yatim. Doc vs kode beda soal route → §7.3a percaya KODE + tandai doc basi.
4. **HAPUS berlapis-DB:** JANGAN hapus file migrasi ter-apply (wajib migrasi-turun BARU + rollback §9 — hapus file tak meng-undo tabel prod & merusak riwayat); `*.types.ts` generated → wajib regen + `npm run build` (RPC 404 runtime lolos gerbang build); pemanggil di alur LAIN = "harus dibereskan", BUKAN "ikut terhapus".

### Format sajian rencana

Tiap SEKSI UTAMA rencana ditutup pasangan (kedalaman keputusan owner):
- **👨‍🎓 Junior-<profesi>:** inti teknis seksi + jargon dijelaskan di tempat; klaim ber-`berkas:baris` (rujuk singkat — kutipan lengkap di blok penutup).
- **🙂 Non-<profesi>:** 1 kalimat awam (analogi opsional). Maks 1 kalimat; TANPA sub-bullet.

Label = penalaran ikut topik SEKSI (seksi migrasi → Junior-Database), BUKAN router kata-kunci (ADR-009). Rencana sepele → cukup 1 pasangan di atas. **DILARANG menggandakan panjang rencana.**

**Blok penutup "Kondisi nyata dasar rencana"** (kerangka §4.2-0) sebagai tabel Pola-Ditiru + cap-hash:
```
## Pola-Ditiru (diverifikasi pada commit <hash>, <tanggal>)
| Konsern | Sumber (berkas:baris) | Pola |
| ... | ... | ... |

✅ Terverifikasi (kubaca sendiri): <klaim + berkas:baris>
❓ Asumsi/belum dicek: <klaim> + langkah verifikasi
🔗 Yang bergantung: <pemanggil/berkas ikut kena>
```
Sesi eksekusi memakai-ulang blok ✅ ini: cek murah `git diff --name-only <hash>..HEAD` → berkas ber-✅ ikut berubah → verifikasi ulang (selaras §6.1).

**Konfirmasi-lingkup §3** (WAJIB, tetap): yang dibangun · kriteria sukses · yang TIDAK dibangun · risiko. Kriteria-sukses BOLEH pakai pola EARS "KETIKA [kondisi] MAKA SISTEM HARUS [perilaku]" (`workflows/ears-kriteria.md`).

### Pernyataan Cakupan (WAJIB untuk output BACA/SARAN/audit)

Tutup jawaban kondisi/saran dengan: **"✅ Diperiksa: <daftar berkas/objek nyata> · ❓ BELUM diperiksa: <daftar>"**. Ubah mode-gagal (diam-diam yakin di atas subset basi) jadi jujur-parsial. "Klaim penyetir-keputusan" = kalau klaim ini terbalik, langkah/urutan/lingkup rencana ikut berubah (uji-balik). Langkah rencana yang bergantung klaim ❓ diberi silang-rujuk (mis. "⚠️ bergantung ❓2 — verifikasi di awal eksekusi").

### SKIP & pas-ukuran
- Q&A klarifikasi di tengah plan mode ("jadi opsi 1 atau 2?") → jawab pendek TANPA pasangan (bahasa §2.1 tetap).
- Mode Hemat §15: tampilan pasangan = Tingkat-2 (boleh dilonggarkan); substansi ✅/❓ = Tingkat-1 (TIDAK).
- Blok 🎯 Tinjauan §4.1 + 📚 Belajar §4.1b: kapan-tampil TIDAK berubah; blok 📚 tetap SEKALI di penutup (terpisah dari pasangan §4.19 — beda fungsi: §4.19 = format isi rencana, §4.1b = penutup pelajaran).

### Pagar anti-ngarang (tak bisa dilonggarkan, rujuk §8.2)
- `berkas:baris` WAJIB nyata — verifikasi via Read/Grep sebelum ditulis. Belum dibaca → ❓, JANGAN dipromosikan ke ✅.
- **Klaim kelengkapan/negasi** ("semua pemanggil = ...", "tidak ada auth") DILARANG ✅ dari SATU grep — tulis ❓ + pola cari + cakupan ("sudah kucari `pola` di src/, nihil"). ✅ bukti-nihil yang menyebut cara carinya tetap SAH.
- Nol-asumsi itu SAH; daftar ❓ jujur > daftar ✅ karangan. DILARANG menobatkan ✅ prematur demi berhenti (lantai ambang wajib).

### Doktrin navigasi-vs-bukti (jawaban Q2 owner)
Peta/kartu/tabel-kandidat = **NAVIGASI, BUKAN bukti** — ✅ HANYA lahir dari membaca KODE ASLI atau output tool deterministik yang dikutip (Read/Grep/ls, §8.2 Aturan 1; §7.3a "dokumen menavigasi, kode asli mengubah"). Peta vs kode bertentangan → percaya kode + perbaiki peta. Kecepatan = lapisan navigasi (baca sedikit tapi tepat); kepastian = klaim tetap dari kode.

### Contoh terisi

> **ILUSTRASI FIKTIF — path/baris/tanda ✅ di bawah JANGAN disalin ke rencana nyata; tiap ✅ wajib lahir dari pembacaan sesi ini (§8.2).**

**Contoh 1 — rencana penuh 2 seksi ("tambah kolom telepon + tampil di form profil"):**
```
## Seksi 1 — Migrasi DB: kolom `phone` di tabel profil
- Migrasi 042 (expand): ALTER TABLE profiles ADD COLUMN phone TEXT + RLS own-row.
👨‍🎓 Junior-Database: kolom baru = fase expand murni (backward-compatible); RLS own-row via auth.uid() — pola sama profiles_username (migrations/031).
🙂 Non-Database: kita tambah kotak "nomor telepon" di data pengguna, tiap orang cuma bisa ubah miliknya.

## Seksi 2 — Form profil (Next.js)
- Field phone di app/account/form.tsx; validasi zod; simpan via RPC.
👨‍🎓 Junior-Frontend: reuse pola form settings (app/account/form.tsx) + zodResolver; 4-state UI.
🙂 Non-Frontend: tambah isian nomor di halaman akun, ada tombol simpan + pesan sukses/gagal.

## Pola-Ditiru (diverifikasi pada commit a1b2c3d, 2026-01-01)
| Konsern | Sumber | Pola |
| Migrasi kolom | migrations/031_username.sql | ADD COLUMN IF NOT EXISTS + RLS own-row |
✅ Terverifikasi: tabel profiles ada (migrations/001:12); pola RPC self-update (migrations/031:20).
❓ Belum dicek: apakah form akun sudah punya field lain (verifikasi: baca app/account/form.tsx di awal eksekusi).
🔗 Bergantung: regen types setelah migrasi.

Konfirmasi-lingkup: dibangun = kolom+form phone · kriteria sukses = KETIKA user simpan nomor valid MAKA SISTEM HARUS menyimpan & menampilkannya setelah reload · TIDAK dibangun = verifikasi OTP/notifikasi · risiko = lupa regen types → build gagal.
```

**Contoh 2 — rencana sepele → 1 pasangan** (prompt "ganti teks tombol checkout"):
```
Ganti label tombol di app/cart/CheckoutButton.tsx (teks literal JSX, bukan i18n).
👨‍🎓 Junior-Frontend: teks literal di JSX, edit = ganti string 1 berkas; tak ada layer terjemahan.
```

(Catatan: di luar Plan mode, task sepele begini boleh langsung dikerjakan tanpa upacara rencana — §3 "tugas sepele lewati".)

**Contoh 3 — cabang proyek-baru** (prompt "bikin aplikasi kasir dari nol"): blok penutup TANPA ✅ `berkas:baris` itu SAH — isi = ❓ kebutuhan yang belum digali (katalog/transaksi/stok/struk/peran) + rujukan resep `workflows/cap/pembayaran.md` yang akan dipakai. DILARANG mengarang ✅ untuk kode yang belum ada.

**Contoh SKIP** — user tanya "jadi pakai Supabase atau Prisma?" di tengah plan mode → jawab pendek langsung (rekomendasi + alasan), tanpa pasangan 2-versi.
