## 4.3. Guided Step-by-Step Pattern untuk Staff Baru (Universal First-Time Workflow)

Saat staff IT non-programmer pertama kali pakai lintasAI di project apa pun, AI WAJIB pandu step-by-step dengan **pattern wait-for-confirm** — fokus 1 step at a time, konfirm progress sebelum lanjut (jangan overwhelm 14 step sekaligus).

### Trigger Conditions (Kapan AI Auto-Apply)

Auto-apply 6-phase workflow kalau detect salah satu: (1) `docs/architecture.md` baru ter-generate (setup fresh); (2) folder punya `.claude-kit/` tapi `AGENTS.md` masih placeholder `<...>`; (3) user chat *"aku staff baru / baru clone / guide aku"*; (4) owner brief *"ada staff baru join, bantu onboarding"*.

### Wait-For-Confirm Pattern

Pola tiap step: AI tampilkan `📋 Step <N>: <aksi>` + substep konkret + *"tunggu kabar; ketik OK/done kalau sukses, atau jelaskan errornya"* → user balas → AI `✅ Step <N> selesai, lanjut <N+1>?` (kalau OK) atau bantu debug error (kalau gagal).

### Phase 1 - Foundation Verification (AI Auto, ~30 detik)

AI verify struktur tanpa user action:

| Step | Aksi | Wait Konfirm? |
|---|---|---|
| 1.1 | Cek `.claude-kit/` lengkap (semua file kit cocok manifest sha256; jumlah dihitung dari `lib/kit-files.json`, jangan patok angka tetap) | ❌ Auto |
| 1.2 | Cek `AGENTS.md` ada di root project + sudah ter-fill (bukan template `<...>`) | ❌ Auto |
| 1.3 | Cek `docs/` skeleton (architecture.md, glossary.md, _PATTERNS.md, _EXAMPLE.md) | ❌ Auto |
| 1.4 | Cek `.github/workflows/ai-review.yml` ada | ❌ Auto |
| 1.5 | **Report ke user**: "Foundation OK ✅. Semua file kit + AGENTS.md + 4 docs skeleton + AI Reviewer aktif. Lanjut Phase 2 (baca panduan dasar)?" | ✅ Tunggu konfirm |

### Phase 2 - Pre-Work Reading (Day 0, sekali pakai)

Skip phase ini kalau user pernah sebelumnya (cek di memory).

| Step | Aksi | Wait Konfirm? |
|---|---|---|
| 2.1 | "Buka file `docs/GLOSSARY_NON_PROGRAMMER.md`. Baca sambil bayangin analogi (Google Drive, Word, IKEA, dst.). **Estimasi 15 menit**. Ketik 'OK' kalau sudah baca habis." | ✅ Tunggu "OK" |
| 2.2 | "Buka file `docs/SECURITY_INCIDENT_PLAYBOOK.md`. Fokus ke section '6-Step Procedure' + '5 Yang TIDAK BOLEH Dilakukan'. **Estimasi 5 menit**. Ketik 'OK' kalau sudah." | ✅ Tunggu "OK" |
| 2.3 | "Quiz singkat (3 pertanyaan, supaya saya yakin kamu paham):<br>1. Apa beda `main` branch sama feature branch?<br>2. Kalau token bocor, langkah pertama yang kamu lakukan apa?<br>3. Apa itu Risk Level dan kenapa penting?" | ✅ Tunggu jawaban (AI verify) |
| 2.4 | "Foundation reading done ✅. Quiz lulus. Lanjut Phase 3 (load project context)?" | ✅ Tunggu konfirm |

### Phase 3 - Project Context Loading (AI Auto, ~30 detik)

AI baca file project, briefing user:

| Step | Aksi | Wait Konfirm? |
|---|---|---|
| 3.1 | Read `AGENTS.md` + relevant section `CLAUDE_universal_v1.md` | ❌ Auto |
| 3.2 | Read `docs/architecture.md` (peta makro project, kalau ada) | ❌ Auto |
| 3.3 | Read `docs/glossary.md` (kamus istilah domain spesifik project, kalau ada) | ❌ Auto |
| 3.4 | **Briefing 3-5 kalimat** ke user: "Project ini `<nama>`. Stack: `<stack>`. Domain: `<bisnis>`. Status progress: `<X%>`. Focus minggu ini: `<topik>`. Tech stack default: Tailwind + shadcn/ui." | ✅ Tunggu konfirm "OK paham" |

### Phase 4 - Environment Setup (Per project, sesuai stack)

| Step | Aksi | Wait Konfirm? |
|---|---|---|
| 4.1 | "Owner sudah DM kamu password DB + .env values? Kalau belum, lapor owner dulu. Ketik 'OK' kalau sudah terima." | ✅ Tunggu konfirm |
| 4.2 | "Sekarang jalankan: `<pasang>`. Tunggu sampai selesai (3-5 menit). Lapor kalau ada error." | ✅ Tunggu "selesai" |
| 4.3 | "Setup `.env.local`: copy dari template `.env.example`, paste isi yang owner DM. WAJIB cek file extension `.env.local` (bukan `.env.local.txt`)." | ✅ Tunggu konfirm |
| 4.4 | "Generate Prisma client (skip kalau project tidak pakai Prisma): `npx prisma generate`. Tanpa step ini, dev server crash." | ✅ Tunggu "OK" |
| 4.5 | "Run dev server: `<jalan>`. Buka browser ke `localhost:3000`. Lapor kalau halaman load + tidak ada error merah." | ✅ Tunggu "OK halaman load" |

> 🚨 **`<pasang>`/`<jalan>` = perintah yang TERDETEKSI, JANGAN di-hardcode.** Pakai `getPackageManager` (`lib/project-detect.mjs`) atau baca lockfile/`packageManager` di `package.json` → `npm install`/`npm run dev` di project npm, `pnpm install`/`pnpm dev` di project pnpm, dst. Meng-hardcode salah satu **merusak lockfile** project yang memakai alat lain (aturan sama: `JALANKAN_KIT.md` §303 + `AUDIT_POST_SETUP_PROMPT_v1.md` §269). Sebutkan perintah yang SUDAH terdeteksi ke staff — jangan suruh dia memilih.

### Phase 5 - First Task (Test Workflow End-to-End)

Phase 5 punya **2 variant** (AI tanya dulu): **(A) Test latihan** — owner kirim micro-task ringan (fix typo, ganti tahun copyright) untuk hands-on tanpa risiko (cocok hari pertama); **(B) Langsung task real** — staff sudah punya brief dari owner.

#### Variant A / Variant B

Langkah **identik** (Pattern-Driven → branch → code → commit → push → PR → verify preview → lapor owner); beda cuma asal task.

| Step | Aksi | Wait Konfirm? |
|---|---|---|
| 1 | **A:** minta owner kirim micro-task latihan via chat, paste ke AI. · **B:** staff brief task (paste chat owner / natural language "owner suruh tambah fitur Y di halaman Z"). | ✅ Tunggu task/brief |
| 2 | Apply Pattern-Driven Workflow (section 4.2): AI tanya AC + risk level + reuse | ✅ Tunggu jawaban |
| 3 | AI eksekusi: `git checkout -b <branch>` → edit file → `git commit` → `git push` → `gh pr create` | ✅ Tunggu konfirm tiap mikro-step |
| 4 | "Tunggu 2-3 menit, Vercel kasih preview URL di komentar PR. Buka URL, verify perubahan kelihatan." | ✅ Tunggu "OK kelihatan" |
| 5 | "Lapor owner di channel chat: 'PR siap review: <link>, preview: <link>'." → owner review + merge | ✅ Tunggu konfirm "owner merged" |

### Phase 6 - Daily Work Starts (Closing)

| Step | Aksi |
|---|---|
| 6.1 | **AI closing message (neutral)**: "🎉 Onboarding selesai! Kamu sudah hands-on workflow lengkap (branch→PR→preview→merge→deploy). **Aturan harian**: (1) tiap task baru = sesi FRESH; (2) chat bahasa natural, AI auto-apply pattern PROMPT_LIBRARY; (3) tiap jawaban substantif ditutup blok belajar **📚 Belajar dari task ini** — sedangkan blok **🎯 Tinjauan lintasAI Divisi** muncul HANYA kalau ada temuan nyata / keputusan besar (task rutin yang bersih memang TANPA blok itu — itu normal, bukan AI-nya malas); (4) security alert → `docs/SECURITY_INCIDENT_PLAYBOOK.md`; (5) bingung istilah → `docs/GLOSSARY_NON_PROGRAMMER.md`. Brief saya kapan pun siap mulai. 🚀" |

### Project Setengah Jadi vs Fresh Project

Pattern 6-phase berlaku UNIVERSAL untuk fresh project ATAU project setengah jadi (clone existing repo dengan code). Bedanya cuma di Phase 3 + 4 + 5:

#### Fresh Project (folder baru, belum ada code)

- **Phase 3** briefing singkat: *"Project baru, belum ada code yang signifikan. Kamu akan mulai dari nol sesuai brief owner."*
- **Phase 4** env setup minimal: cuma `.env.local` + `<pasang>` (mungkin belum ada Prisma schema)
- **Phase 5** Variant A WAJIB (test workflow dengan task latihan dulu - staff belum punya konteks)

#### Project Setengah Jadi (clone existing repo)

- **Phase 3** briefing EKSTENSIVE (5-10 kalimat):
  - Stack lengkap dari `package.json` + framework version
  - Domain bisnis (dari `architecture.md`)
  - Status progress (mis. "5% - fokus auth + landing page")
  - File CRITICAL yang sudah punya `.md` vs belum (pakai `Grep`)
  - Active focus area minggu ini
- **Phase 4** env setup lengkap: `<pasang>` + `.env.local` + `npx prisma generate` (kalau pakai Prisma) + `<jalan>` + **verify halaman load di browser**
- **Phase 5** AI tanya Variant A/B (lihat tabel Phase 5 di atas); di project setengah-jadi mayoritas **Variant B** (staff sudah punya brief task dari owner)

**Aturan tambahan untuk Project Setengah Jadi**:
- Pakai `docs/architecture.md` + `Grep` untuk temukan file CRITICAL existing
- Briefing termasuk: *"Project ini sudah ada N file CRITICAL dengan docs, M file belum. Mau scan dulu (Phase Bulk-Bootstrap di `PROJECT_LIFECYCLE_PROMPT_v1.md` Stage 2: Bikin Catatan Proyek) atau langsung task?"*
- Kalau staff pilih langsung task → AI tawarkan bikin `.md` saat staff sentuh file CRITICAL yang belum punya docs (on-demand)

### Trigger Detection - Project Setengah Jadi vs Fresh

Auto-detect: **Fresh** = `src/` kosong/1-2 boilerplate + `package.json` minimal; **Setengah Jadi** = banyak file source + dependency ekstensif + `prisma/schema.prisma` banyak model. Pilih variant Phase 3-5 otomatis, lapor + confirm ke user.

### Aturan Tambahan

- **Skip phase yang selesai**: re-trigger (project ke-2) → skip Phase 2, straight ke Phase 3.
- **Adapt per stack**: step 4.4 (Prisma generate) skip kalau non-Prisma (detect dari `package.json`).
- **Tone ramah**: seperti mentor senior bantu junior; jangan formal kaku.
- **Error tolerance**: user error di step mana pun → guide debug dulu, jangan biarkan stuck.
- **Persistence**: sesi ditutup di tengah → sesi berikut cek progress + resume dari step relevan.

### Filosofi

Staff non-programmer fase awal butuh **hand-holding intentional** — bukan soal kapabilitas, tapi cognitive load (git + task + AI workflow sekaligus) terlalu tinggi untuk self-service. Guided workflow = "kursi roda training" Day 0-1; Day 7+ staff lepas, kerja independen.
