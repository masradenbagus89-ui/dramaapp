## 4.4. Audit Post-Setup Pattern (Otomatis Setelah Stage 1/2 atau Standalone)

Setelah `PROJECT_LIFECYCLE_PROMPT_v1.md` Stage 1/2 selesai (atau user brief "audit"/"review"/"cek apa yang bisa diperbaiki"), AI WAJIB tawarkan **AUDIT KOMPREHENSIF MULTI-DIMENSIONAL** dengan **ANALOGI NON-PROGRAMMER**. Workflow lengkap: `./.claude-kit/AUDIT_POST_SETUP_PROMPT_v1.md`.

### Kapan AI auto-trigger audit offer

1. **Setelah Stage 1/2 closing** atau **`setup-pola-b.mjs` Phase 5b selesai** — AI tutup dengan offer audit (read-only, ranked low→high risk, analogi non-programmer; paste `AUDIT_POST_SETUP_PROMPT_v1.md` atau "ya").
2. **User brief eksplisit**: "audit/review codebase", "cari bug + refactor", "apa yang bisa diperbaiki", "scan menyeluruh".
3. **Setelah refactor besar** (extract helper cross-module, schema migration) → suggest audit ulang (verify behavior unchanged).
4. **Sebelum hire staff** → owner "project siap belum?" → auto-trigger audit + rencana bertahap.

### Format finding WAJIB pakai analogi non-programmer

Tiap finding dari audit HARUS punya 6 field:

```markdown
**[N] <Title teknis singkat>**
- 📖 **Analogi**: <bahasa sehari-hari pakai contoh kantor / lemari arsip / ATM / tukang pos / brankas>
- 🎯 **Kenapa penting**: <1-2 kalimat awam, tanpa jargon>
- 🛠 **Fix**: <pointer cepat, sebut file/line dan langkah kasar>
- ⏱ <effort: 5min / 30min / 2hr / 8hr+ / multi-day>
- 🚦 <tingkat: GENTING / PENTING / RAPIKAN>
- ⚠ Risiko bikin rusak: <RENDAH / SEDANG / TINGGI>
```

### Style guide analogi (mapping jargon → bahasa awam + tools digital populer)

**WAJIB**: tiap finding audit yang memuat jargon teknis **dijelaskan dengan bahasa awam** (1 kalimat yang mudah dipahami) — jargon TIDAK dibiarkan mentah. **TIDAK wajib** bentuk 3-lapis; **1 analogi singkat opsional** kalau membantu. Daftar di bawah = **bahan analogi OPSIONAL** (kalau mau pakai 1), bukan kewajiban 3-lapis. *(Disederhanakan per keputusan owner 2026-06-25.)*

1. **🏢 Sehari-hari**: analogi kantor / dapur / lemari arsip / loket bank - universal, no tools knowledge.
2. **📱 Tools digital populer**: analogi pakai fitur familiar Indonesia-context (Tokopedia, Gojek, WhatsApp, BCA mobile, Excel, Google Drive, dst.) - staff yang familiar dengan tools tersebut langsung paham.
3. **🎯 Contoh konkret**: kapan situasi ini muncul di proyek (1 kalimat).

**Bahan analogi (opsional)** — kalau mau pakai 1 analogi untuk jargon: contoh sehari-hari (rumah/kantor/sekolah) + tools populer Indonesia (Tokopedia, Shopee, Gojek, WhatsApp, BCA mobile, Excel, Google Drive, Notion, Discord, YouTube, iPhone). Contoh grounding: Prisma = lemari arsip (struktur jelas); Migration = upgrade WhatsApp Web (data format lama→baru); RLS = privasi WhatsApp (cuma lihat chat sendiri); Schema = template Notion; Env var = PIN BCA (rahasia). Library: `docs/ANALOGI_LIBRARY.md` (auto-deploy `setup-pola-b.mjs` dari `templates/ANALOGI_LIBRARY.md`). Istilah baru di luar library → jelaskan bahasa awam 1 kalimat + boleh suggest tambah.

**Kategori tools untuk analogi (Indonesia-context):** E-commerce (Tokopedia/Shopee/Bukalapak) · Transport (Gojek/Grab) · Komunikasi (WhatsApp/Telegram) · Sosial (Instagram/TikTok) · Produktivitas (Google Drive/Docs/Sheets, Excel, Notion) · Desain (Canva) · Team comm (Discord/Slack) · Video (YouTube/Netflix) · HP (iPhone/Android) · Banking (BCA mobile/BRImo/Livin/Jenius) · Food delivery (GoFood/GrabFood/ShopeeFood).

### Filosofi audit dengan analogi

1. **READ-ONLY by default**: audit cuma scan + laporan (tak ada `Edit`/`Write`); user pegang kontrol "fix yang mana".
2. **Ranked low → high risk**: quick wins `risk_of_introducing_bug=low` jadi prioritas.
3. **Penjelasan awam WAJIB**: tiap jargon dijelaskan bahasa awam 1 kalimat (1 analogi opsional). Jargon mentah = bukan audit lintasAI standard.
4. **Adversarial verify**: default `is_real=false` kalau verifier tak 100% yakin (cegah inflate jumlah finding).
5. **Rencana bertahap = guidance, BUKAN auto-execute**. Owner pilih per-finding; AI execute dengan safety net.

### Default execution (bagian Pattern-Driven Workflow)

Intent staff yang map ke pattern audit (semua → `AUDIT_POST_SETUP_PROMPT_v1.md`): "audit/review/scan menyeluruh" (workflow lengkap) · "ada bug/apa yang salah" (fokus security+qa) · "perbaiki performa/apa yang lambat" (fokus database+performance) · "ready hire staff/siap onboarding" (fokus onboarding+docs gap) · "refactor/DRY/extract helper" (fokus refactor). Detail workflow + Popup #1 (pilih tier) + Popup #2 (lanjut/write report/pick item/stop) di `./.claude-kit/AUDIT_POST_SETUP_PROMPT_v1.md`.
