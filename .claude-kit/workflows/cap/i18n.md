## §i18n. Capability Pack — i18n (banyak bahasa / lokalisasi) kelas-industri

> **Kapan dibaca:** "dukung banyak bahasa / terjemahan / ganti bahasa / multi-bahasa / lokalisasi / format mata uang-tanggal / bahasa Arab (kanan-ke-kiri)". Resep merakit dukungan multi-bahasa yang **benar secara linguistik & tak bikin bug tata-letak**. Baca induk `workflows/cap-packs.md`.

> **i18n** = *internationalization* (menyiapkan aplikasi supaya BISA diterjemahkan); **l10n** = *localization* (mengisi terjemahan & format untuk satu wilayah).

🙂 Analogi: i18n = **menu restoran multi-bahasa**. Teksnya dipisah dari "dapur" (kode) supaya bisa diganti tanpa memasak ulang; angka, tanggal, dan mata uang mengikuti kebiasaan setempat (Rp10.000 vs $10.00).

### Kontrak (yang harus benar)
- **Input:** teks UI + data lokal (tanggal, angka, mata uang, zona waktu) + pilihan bahasa user. **Output:** tampilan sesuai bahasa & kebiasaan wilayah, tata-letak tetap rapi. **Aman:** teks terjemahan/user tetap **di-escape** (cegah XSS); jangan taruh rahasia di bundel terjemahan yang dikirim ke browser.

### Langkah rakit (prinsip — cek dokumentasi library versi terpasang §8.2)
1. **Pisah teks dari kode SEJAK AWAL (§10).** Semua string UI di **file terjemahan** (kunci → teks per bahasa), bukan ditulis langsung (hardcode) di komponen. Menyisipkan i18n ke aplikasi yang sudah penuh teks hardcode = pekerjaan berat — mulai benar dari awal jauh lebih murah. Deklarasikan bahasa halaman (`<html lang="id">`).
2. **Pakai library i18n teruji** (next-intl / i18next / react-intl, Django i18n, Laravel `lang`) — **jangan** bikin sistem terjemahan sendiri (rawan salah plural & format).
3. **Pluralisasi ikut aturan bahasa, bukan `if (n>1) tambah "s"`.** Bahasa berbeda punya bentuk jamak berbeda (Inggris 2 bentuk, Arab 6, Indonesia tak mengubah kata). Pakai **ICU MessageFormat / plural rules** dari library — jangan rakit manual.
4. **Format lokal pakai `Intl` / API bawaan, bukan manual:** tanggal, angka, mata uang, persen lewat `Intl.DateTimeFormat`/`Intl.NumberFormat` (atau padanan framework). **Simpan waktu dalam UTC di DB, tampilkan dalam zona lokal user** — jangan simpan waktu lokal mentah.
5. **Jangan gabung kalimat dari potongan.** ❌ `"Anda punya " + n + " pesan"` — urutan kata & bentuk beda antar-bahasa. ✅ satu pesan ber-placeholder: `t('pesan.jumlah', { count: n })`. Terjemahkan **kalimat utuh**, bukan kepingan kata.
6. **Arah teks (RTL) untuk Arab/Ibrani/Persia:** teks mengalir **kanan-ke-kiri**. Pakai properti **logis** (`margin-inline-start`, `text-align: start`) bukan `left`/`right`, dan set atribut `dir="rtl"`. Uji tata-letak di mode RTL.
7. **Rencanakan ekspansi teks:** terjemahan bisa jauh lebih panjang (Jerman ~30% lebih panjang dari Inggris) — jangan pakai lebar/tinggi tetap yang memotong teks; sediakan fallback ke bahasa default kalau kunci terjemahan kosong.
8. **SEO multi-bahasa (halaman publik):** URL per-bahasa (`/id/…`, `/en/…`) + tag **`hreflang`** supaya Google tahu versi bahasa mana untuk siapa (rujuk `workflows/stack/4.14-6-seo.md`).

### Gotcha (sering salah)
- **Teks hardcode di komponen** → tak bisa diterjemahkan tanpa bongkar kode. Pisahkan dari awal.
- **Gabung kalimat dari potongan** → terjemahan janggal/salah urutan di bahasa lain.
- **Plural naif (`+"s"`)** → salah di hampir semua bahasa non-Inggris.
- **Format tanggal/angka manual** → `07/12` ambigu (Juli-12 vs 7-Des); pakai `Intl`.
- **Lupa RTL** → tata-letak Arab berantakan (ikon & panah terbalik).
- **Lebar tetap** → teks bahasa panjang terpotong (`...`).
- **Terjemahan/teks user di-render sebagai HTML tanpa escape** → XSS. Escape tetap wajib.

### Rujuk-silang (reuse-first — jangan salin)
- Pisah-teks-dari-kode + a11y + `lang` → baseline Frontend/UX (§10) & `workflows/stack/4.14-1-nextjs.md`.
- `hreflang` + URL per-bahasa (SEO) → `workflows/stack/4.14-6-seo.md`.
- Escape output (anti-XSS) → `workflows/stack/4.14-5-owasp.md`.
- i18n frontend mendalam (routing bahasa, lazy-load pesan) = peta-jalan `stack/4.14-1d-i18n`.

### Threat-model 3-baris
- **Aset:** kebenaran & keamanan konten lintas-bahasa. **Risiko:** teks terjemahan/user ter-render sebagai HTML (XSS), rahasia bocor lewat bundel terjemahan yang terkirim ke klien, kebocoran data lewat kunci yang salah tampil. **Mitigasi:** escape output tetap wajib + jangan taruh secret di file terjemahan klien + tinjau kontribusi terjemahan.

### Batas jujur
Pack ini menyiapkan aplikasi agar BISA diterjemahkan dengan benar; **kualitas terjemahan** tetap butuh penerjemah manusia/profesional (mesin bisa keliru konteks). Lokalisasi penuh (mata uang, format alamat, aturan pajak per-negara) bisa jauh lebih dalam. Cek dokumentasi resmi library i18n **versi terpasang** — API pemuatan pesan & konfigurasi routing bahasa berbeda antar-framework.
