Isi penuh `skills/deploy/SKILL.md` §2 butir 7-9 — template pipeline, alat pemindai keamanan (SAST·SCA·secret·container·DAST·SBOM), IAM/WAF/backup-DR.

7. 📐 **Pipeline CI/CD otomatis (test → build → deploy) — template siap-pakai.** Template GitHub Actions 3-tahap ada di `templates/github/workflows/app-cicd.yml.example` (client: `.lintasai/templates/github/workflows/`). `test` (lint + typecheck + test + coverage) jalan di SEMUA push/PR; `build` + `deploy` hanya di `main` (bangun image Docker → kirim ke ghcr.io → tayang). Versi action di-pin ke **terbaru terverifikasi 2026-07-11**: `checkout@v7`, `setup-node@v6` (WAJIB `cache: "npm"` eksplisit — cache auto kini npm-only), `build-push@v7`, cache `type=gha`. Salin ke `.github/workflows/app-cicd.yml` (buang `.example`) + sesuaikan langkah `deploy` per platform. Job `build` pakai `permissions: packages: write` (hak seperlunya) + `GITHUB_TOKEN` bawaan.
   - 🙂 Non-Programmer: proses otomatis — kode dikirim → diuji → dikemas → ditayangkan; kalau gagal di tengah jalan, prosesnya berhenti (kode rusak tak ikut tayang). Cukup salin contohnya, isi bagian "kirim ke server".
8. 📐 **Gerbang keamanan otomatis di pipeline (SAST · SCA · secret · container · DAST · SBOM).** Uji kode CEPAT & OTOMATIS tiap PR — jauh lebih murah daripada ketahuan setelah bocor. Tiap alat menutup lapisan berbeda; tak perlu semua sekaligus (lihat label WAJIB/DISARANKAN/OPSIONAL):
   - **SCA — dependency rentan (WAJIB).** Cek CVE (celah publik) di paket pihak-ketiga. Jalankan `npm audit` (Node) / `govulncheck` (Go) sesuai stack. TAMBAH untuk berkelanjutan: **Dependabot/Renovate** (PR otomatis saat ada versi patch) + `pip-audit` (Python). = OWASP A03:2025 → `skills/owasp/SKILL.md`.
   - **SAST — baca kode cari celah (DISARANKAN).** SAST (*Static Application Security Testing* = periksa kode TANPA menjalankannya). Kit SUDAH: `bandit` (Python). TAMBAH untuk JS/TS: `semgrep --config auto` (multi-bahasa, cepat) atau **CodeQL** (gratis untuk repo publik / GitHub Advanced Security). Cek nama paket di registry sebelum pasang.
   - **Secret scan (WAJIB).** Kit SUDAH: pre-commit `secret-guard` + workflow CI (cegah `.env`/kunci ter-commit). Pelengkap server-side: GitHub Secret Scanning.
   - **Container scan (kalau pakai Docker).** `trivy image <img>` = pindai CVE base image + dependency; jalankan di CI sebelum push image (lengkapi Dockerfile — butir 12 di `skills/deploy/rujukan/env-health-docker.md`).
   - **DAST — uji app BERJALAN (OPSIONAL, untuk app publik matang).** DAST (*Dynamic Application Security Testing* = "serang" app hidup di staging). **OWASP ZAP** baseline scan; berat → jadwalkan berkala, bukan tiap PR.
   - **SBOM — daftar-isi dependency (OPSIONAL).** Hasilkan CycloneDX (`@cyclonedx/cyclonedx-npm`) → saat ada celah paket global (mis. Log4Shell), cepat tahu "apakah kita terdampak?". = OWASP A03:2025.
   - 🙂 Non-Programmer: alat pemindai otomatis dipasang di pipeline — ada yang cek dependency rentan (SCA), yang baca kode cari celah (SAST), yang cari rahasia yang bocor (secret scan), yang periksa image container (container scan), dan yang menguji app yang sedang berjalan (DAST). Wajib minimal 2 pertama; sisanya menyusul sesuai kebutuhan.
9. 📐 **Keamanan infra cloud (IAM · WAF · backup/DR).** Aplikasi aman tapi infra cloud-nya bocor = sama saja bocor. 3 blok: pengaturan akun cloud, penyaring serangan (WAF), cadangan data — disuling untuk stack PaaS terkelola (Vercel/Railway/Render + Cloudflare + Supabase), bukan AWS mentah.
   - **Akses akun cloud** (IAM = *Identity & Access Management*, pengaturan siapa-boleh-apa):
     - **MFA WAJIB** di semua akun admin: GitHub org, Vercel/Railway/Render, Supabase, Cloudflare, registrar domain. Akun root/owner JANGAN dipakai kerja harian — buat akun per-orang dengan hak minimum (default deny).
     - **Token API ber-scope sempit + berumur pendek**; untuk CI→cloud pakai **OIDC** (saling-percaya antar-layanan TANPA menyimpan kunci berumur-panjang — kit sendiri memakainya untuk publish npm). `GITHUB_TOKEN` di workflow: blok `permissions:` minimum — sudah dicontohkan template CI/CD (butir 7).
     - **Tinjau akses berkala:** staff keluar = cabut aksesnya HARI ITU; token/kredensial tak terpakai = hapus; audit "siapa pegang apa" tiap kuartal.
   - **Pin action pihak-ketiga ke commit SHA penuh (supply-chain CI).** Tag (`@v45`) BISA DIPINDAH penyerang — insiden nyata `tj-actions/changed-files` (CVE-2025-30066, Mar 2025, CVSS 8.6 + masuk katalog KEV CISA): tag v1–v45.0.7 dialihkan ke commit jahat yang membocorkan secret ke log CI ribuan repo. Dok resmi GitHub: SHA penuh = "satu-satunya cara memakai action sebagai rilis kekal (immutable)". Praktik: `uses: pihak/aksi@<sha-40-digit> # v45.0.7` + biarkan Dependabot yang menaikkan SHA-nya. Action resmi (`actions/*`) berisiko lebih rendah — prioritaskan pin-SHA untuk pihak-ketiga.
   - **WAF Cloudflare** (*Web Application Firewall* = penyaring serangan di depan situs): aktifkan **managed ruleset** — sadar-plan (dicek 2026-07): plan Free hanya dapat "Free Managed Ruleset" (celah high-impact saja); **Cloudflare Managed Ruleset + OWASP Core Ruleset butuh plan Pro ke atas**. Lengkapi: rate limiting rules + bot protection + mode SSL/TLS **Full (strict)**. WAF = lapisan TAMBAHAN di depan, BUKAN pengganti validasi di server.
   - **Backup/DR** (*Disaster Recovery* = rencana pulih dari bencana):
     - **Supabase** (dicek 2026-07): backup harian otomatis HANYA plan berbayar — Pro 7 hari · Team 14 · Enterprise 30; **plan Free TIDAK di-backup otomatis** → wajib ekspor manual/terjadwal via CLI. Butuh pulih presisi? **PITR** (*Point-in-Time Recovery* = mundur ke titik waktu tertentu) = add-on Pro+ (butuh compute Small+; arsip WAL tiap 2 menit → data hilang terburuk ~2 menit; catatan: PITR MENGGANTIKAN backup harian).
     - **Uji-restore berkala (minimal tiap kuartal):** backup yang tak pernah diuji-pulihkan = BELUM punya backup. Latih pulihkan ke project staging + tulis langkahnya jadi runbook di folder milik project sendiri (mis. buat `docs/runbooks/` — kit tak menyediakannya).
     - **Tetapkan 2 angka keputusan-OWNER (bukan teknisi): RPO** (*Recovery Point Objective* = maksimal data yang rela hilang, mis. "1 jam terakhir") + **RTO** (*Recovery Time Objective* = maksimal lama boleh mati, mis. "4 jam") — semua setelan backup mengikuti 2 angka ini.
     - **Proteksi-hapus:** CI/staff junior JANGAN diberi hak menghapus project/DB produksi; aset non-DB (file upload di storage) ikut di-backup — database pulih tapi foto pelanggan hilang = tetap bencana.
   - 🙂 Non-Programmer: tiga lapis keamanan infra — (1) akses akun dibagi per-orang seperlunya, akun utama disimpan bukan dipakai harian; (2) penyaring serangan di depan situs; (3) salinan cadangan data yang RUTIN dicoba dipulihkan — plus dua angka keputusan bisnis: berapa banyak data rela hilang + berapa lama layanan boleh mati.
